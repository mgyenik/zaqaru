# N5 — the same stack traced both ways, and every difference accounted for
#
# `strace -f` over the native container against kisal's own trace of the
# interpreted one, on the same scenario: boot, two `curl` requests, a
# `SIGTERM` shutdown. Regenerate with `demo/hello-django/trace.sh` for the
# native side and `diff.py` for the comparison.
#
# THE VERDICT: every divergence has a cause, and one cause explains 6,455 of
# the 6,621 extra calls.
#
# 1. THE vDSO IS ABSENT, and that is the whole of the clock difference. The
#    native trace makes **zero** clock syscalls — glibc reads the time out of
#    a page the kernel maps into userspace, which no `strace` ever sees.
#    There is no vDSO here and `AT_SYSINFO_EHDR` is absent from the auxiliary
#    vector, so glibc takes the syscall path it keeps for exactly that case.
#    `clock_gettime`, `gettimeofday`, `time`, `clock_getres` and
#    `sched_getaffinity` are all this. It is a deliberate divergence, it was
#    documented in the `clock_gettime` row long before this diff, and closing
#    it means building a vDSO — which is a real option and not a defect.
#
# 2. `kill` is the two shutdowns differing. N0's was signalled from *inside*
#    the container, by a shell run with `docker exec`, because `docker stop`
#    signals pid 1 which under tracing is `strace` itself. The interpreted
#    run's arrives from the host at pid 1 directly, so no guest process calls
#    `kill` at all.
#
# 3. `madvise`, `exit` and `getpeername` are one call each, and each is a
#    moment one run reached and the other had not: glibc's allocator
#    returning a span, gunicorn's control-socket thread finishing, and
#    gunicorn probing a listener with `getpeername`. Neither run is missing
#    a capability; they were stopped at different points in the same work.
#
# What is NOT here is as important: no call appears in the native trace that
# this kernel would have refused, and no shared call's count differs by more
# than a factor of two.
#
