# N5 — the same stack traced both ways, and every difference accounted for
#
# `strace -f` over the native container against kisal's own trace of the
# interpreted one, on the same scenario: boot, two `curl` requests, a
# `SIGTERM` shutdown. Regenerate with `demo/hello-django/trace.sh` for the
# native side, `trace-interpreted.sh` for the other, and `diff.py` for the
# comparison.
#
# THE VERDICT: five single calls, and each has a cause.
#
# The clock used to be the whole story — 6,455 extra calls, because there was
# no vDSO and glibc took the syscall path it keeps for exactly that case.
# `kisal/src/vdso.rs` closed it: the kernel publishes a timebase against the
# retired-instruction counter and glibc computes the time itself, so a
# container that reads the clock two thousand times issues no clock syscall
# at all. The count went from 15,986 to 9,532 against a native 9,365.
#
# 1. `kill` is the two shutdowns differing. N0's was signalled from *inside*
#    the container, by a shell run with `docker exec`, because `docker stop`
#    signals pid 1 which under tracing is `strace` itself. The interpreted
#    run's arrives from the host at pid 1 directly, so no guest process
#    calls `kill` at all.
#
# 2. `madvise`, `exit` and `getpeername` are one call each, and each is a
#    moment one run reached and the other had not: glibc's allocator
#    returning a span, a thread finishing, and gunicorn probing a listener.
#    Neither run is missing a capability; they were stopped at different
#    points in the same work.
#
# 3. `sched_getaffinity` is asked once by CPython and answered from a
#    cached value natively.
#
# What is NOT here matters as much: no call appears in the native trace that
# this kernel would have refused, and no shared call's count differs by more
# than a factor of two.
#
native:       88 syscalls,   9365 calls
interpreted:  85 syscalls,   9532 calls
